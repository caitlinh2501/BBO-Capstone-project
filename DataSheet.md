# Datasheet: Eight-Function Black-Box Optimisation Project

## Motivation

The purpose of this datasheet is to support sequential BBO tasks involving 8 unknown functions. 
The aim of the project is to identify inputs that maximise each function while working with limited expensive queries. 

The underlying function is unknown - each new datapoint had to be generated by submitting an input vector and receiving the function value. 
This dataset has therefore grown throughout the project. 
The purpose of the dataset is to support surrogate modelling and Bayesian optimisation. 
In particular, the accumulated observations were used to fit the GP models, estimate promising regions and select the next query for each function. 
The dataset also supports analysis of how optimisation decisions change over time. 

## Composition
The dataset contains observed input and output pairs for 8 functions. 
The data are stored as NumPy arrays, with separate input and output files for each function. 
Inputs are stored as two-dimensional arrays of shape (n, d), where n is the number of observations and d is the input dimensionality, while outputs are stored as one-dimensional arrays containing the corresponding objective values. 
There are no missing values within individual observations. However, the dataset is intentionally sparse relative to the size of each continuous search space. 
This is particularly important for the higher-dimensional functions, where only a very small proportion of the possible domain has been explored.

## Collection Process
The dataset was generated sequentially over the duration of the project. 
One new query per function was added per week. 
Candidate inputs were generated using a mix of local sampling around the best area, wider searches around promising regions and global candidate sampling for comparison. 
This was important when the model showed poor calibration. 
For example, some functions produced observations several predicted standard deviations away from the GP mean. 
In these cases, later searches were made more conservative rather than assuming that the model uncertainty was fully reliable.

## Preprocessing and transformations
Most functions were modelled directly using their observed objective values, with output normalisation performed internally by the Gaussian Process model.
There were two exceptions.
For Function 1, the objective values were extremely close to zero in the best-performing region while some other observations were much more negative. 
A positive linear scaling was therefore applied in the final approach. Earlier experiments also explored a logarithmic transformation; this was not retained for the final original-objective maximisation. 

For Function 5, outputs were manually standardised before fitting the Gaussian Process. Predictions were converted back to the original scale for interpretation.
Input variables were already constrained to [0,1], so no additional input scaling was required.

## Intended uses

The dataset is intended for:

Fitting and evaluating surrogate models for black-box optimisation;
Reproducing the optimisation decisions made during the project;
Studying sequential Bayesian optimisation behaviour;
Examining exploration versus exploitation decisions;
Analysing GP uncertainty and calibration;
Comparing observed and predicted function values;
Reflecting on the consequences of adaptive data collection.

## Distribution and maintenance

The dataset was created for the Imperial College London machine learning and artificial intelligence capstone project and is maintained by the project author - Caitlin Hale.
The working data are stored locally as NumPy .npy files, separated by function, with cumulative input and output arrays updated after each optimisation round.
The dataset is primarily intended for assessment, reproducibility and analysis within the capstone project. 
It should not be redistributed publicly unless this is permitted by the course rules and the terms under which the black-box optimisation task was provided.

## Nature of the data and shared modelling details

**Noise and randomness:** the available analysis does not establish whether repeated evaluation of an identical input would return different values. Random candidate generation is part of the search method and does not demonstrate randomness in the objective. The GP white-noise term allows residual variation in the model; it does not prove that the underlying function is noisy. Prediction errors may also reflect model mismatch or sparse coverage.

**Surrogate and preprocessing:** a separate Gaussian Process was fitted for each function. Early experiments used RBF kernels; later notebooks used a constant-amplitude ARD Matérn 5/2 kernel plus a white-noise term. Kernel amplitude, length scales and noise level were fitted through log marginal likelihood optimisation within notebook-specific bounds, with multiple restarts in later rounds. Inputs needed no additional scaling or categorical encoding. Output handling is described above.

**Unusual observations:** the later strategy generally retained observations and investigated prediction errors through calibration checks rather than discarding poor results as outliers. For Function 1, extreme differences in output scale required special treatment. A large standardised residual was treated as evidence to question the surrogate, rather than proof that the returned value was incorrect.

Global and local candidate sampling supplied points for acquisition-based selection. ## Ethical, practical and general considerations

These tasks represent the general structure of real-world optimisation where experiments are expensive and the input-to-outcome relationship is unknown. Examples include process settings or experimental design, but these examples are not claimed to be the official scenarios for Functions 1–8.

Synthetic functions do not establish how the method would perform with real measurement noise, changing conditions, physical constraints or consequences beyond the scalar objective. In a real application, maximising the recorded score alone might overlook costs, harms or other objectives.

The approach could support expensive problems with a modest number of continuous inputs, but scaling would require attention to GP fitting cost, candidate-search cost and increasingly sparse coverage. Higher-dimensional or more consequential problems would require stronger validation, explicit feasibility constraints and domain expertise.

Future users should watch for adaptive sampling bias, GP overconfidence, misleading transformed objectives, boundary effects and the temptation to interpret ARD length scales as proven feature importance. Best observed values, surrogate predictions and claims about the unknown global maximum must remain distinct. Transparent recording of inputs, returned values, preprocessing and selection reasoning is essential.
